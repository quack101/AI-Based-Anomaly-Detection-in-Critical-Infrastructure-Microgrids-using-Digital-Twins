STEP 2 -- STRUCTURAL REFACTOR + DATA-SOURCE FIX

  Per your explicit instruction, FeederContext's data source changed
  too: placement/feeder_adapter.py now builds (network, loads) from

  parser's output). The three deltas below are reported SEPARATELY, in
  the order they were produced, so each is individually attributable.
  Evidence fixtures (committed): tests/fixtures/hybrid_baseline_target49.json

  Config A: captured from the ORIGINAL, unmodified

  load_metadata.json, target_meters=49, BEFORE any edit in this task.
  actual_count = 49.

  Config B: the refactored FeederContext + a Step-3-UNFIXED
  reconstruction of HybridPlacement (same weights including the 1.5x

  OLD data source. actual_count = 49.
  RESULT: Config B == Config A exactly (49/49 identical buses,
  config_b_matches_baseline: true in the fixture). The structural

  DELTA 2 -- topology data-source switch alone (Config B -> C)
  Config C: same Step-3-UNFIXED HybridPlacement as Config B, now fed
  the NEW data source (core.ieee123_model.extract_all() via
  feeder_adapter.py). actual_count = 49.
  Edge count: OLD regex parser = 133 edges, 131 nodes. NEW verified
  source = 131 edges, 132 nodes, 0 cycles -- CONFIRMED correct against
  reports/model_verification_report.txt.
  RESULT: Config C == Config B exactly, 0 buses changed.
  WHY: the regex parser has TWO bugs, not one. (a) It does not
  deduplicate multiple single-phase transformer objects on the same
  bus pair -- reg3a+reg3c both appear as separate 25-25r edges,
  reg4a/b/c all three appear as separate 160-160r edges (7 transformer
  edges total, none deduplicated) -- the same class of bug fixed in
  core/ieee123_model.py's graph builder during model verification
  (FINDINGS #2 there). (b) XFM1's transformer definition uses
  `wdg=.../bus=...` continuation-line syntax, which the parser's
  `buses=\[...\]` regex never matches -- XFM1's edge (61s-610) and bus
  610 itself are silently dropped (confirmed: bus "610" absent from
  network_metadata.json's node list). These two bugs partially offset
  in raw edge COUNT (133 vs 131) but are NOT the same edge set. The
  reason Delta 2 is nonetheless zero: bus 610 hosts no Load object (it
  is XFM1's 0.48kV secondary, below the feeder's spot-load definitions)
  and parallel edges between the same two nodes do not change
  unweighted-BFS depth or branch-ID assignment. Spot-checked directly:
  depth and branch_id are IDENTICAL between old and new topology for
  every load-bearing bus tested (1, 49, 65, 76, 83, 108, 300); only
  topology_graph size differs (124 old vs 125 new, exactly bus 610).
  This does NOT make the fix optional: Q1's radiality/cycle-count
  answer (RES.md D6 A6's graph-cut argument) DOES depend on correct
  deduplication, and a future configuration that reaches bus 610, or a
  much lower meter count where branch topology differences could bite,
  is not guaranteed the same null result. The verified source is now
  the production data source regardless.

  DELTA 3 -- Step-3 defect fixes alone (Config C -> D)
  Config D: the FINAL HybridPlacement (all Step-3 fixes applied) fed
  the NEW data source. actual_count = 49.
  RESULT: 2 of 49 meters changed: removed bus 2 (S2b), bus 12 (S12b);
  added bus 65 (S65c), bus 66 (S66c). Root cause confirmed by
  inspection: buses 2 and 12 are Phase-B, non-backbone; buses 65 (CA)
  and 66 (C) are Phase-C-touching, non-backbone. Both swapped-out and
  swapped-in loads are non-backbone, which rules out the backbone-
  indicator/weight-normalisation change as the cause -- this delta is
  attributable to the phase-balance swap pass specifically (defect
  #2). Achieved phase-kW split after the swap: A=832.5, B=582.5,
  C=675.0 (shares 39.83% / 27.87% / 32.30%) vs. the baseline target
  shares (40.11% / 27.29% / 32.59%) -- within 0.6 percentage points on
  every phase, well inside the 5pp test tolerance.

STEP 3 -- DEFECT FIXES
----------------------------------------------------------------------
  1. Meter count not honoured -- FIXED. _top_up_shortfall() appended
     after the original quota/round-robin logic (which is otherwise
     UNCHANGED -- this is what made Delta 1's exact-equality gate
     possible), filling any shortfall from the highest-scoring
     remaining loads, respecting used_buses. select() now asserts
     len(selected) == target_meters. Verified by parametrized test
     across all 9 sub-study counts (15/30/44/45/49/60/70/80/85).
     Actual current-code behaviour (see Delta 1): target=49 already
     returned 49 before this fix; 45, 70, 80, 85 (and 15) undershot
     and are now fixed.

  2. _balance_phases / _balance_connections no-ops -- PARTIALLY FIXED,
     ONE DROPPED. _balance_phases implemented as a post-selection swap
     pass: for the most over-represented phase (by connected kW share,
     PHASE_KW_BASELINE = A:1400/B:952.5/C:1137.5, per RES.md's explicit
     instruction to balance on kW not node count), swap its lowest-
     scoring selected load for the highest-scoring unselected load on
     the most under-represented phase, stopping when no swap improves
     the maximum deviation from target share. A real bug was found and
     fixed during testing: the swap pass's unselected-candidate pool
     was not deduplicated per bus, so a sibling load on an
     already-selected multi-load bus (e.g. S49b when S49a was already
     selected) could be swapped in, producing a duplicate bus --
     caught by test_no_duplicate_buses at target=30 and 44, fixed by
     routing the candidate pool through the same one-load-per-bus
     collapse Random/DegreePlacement use. _balance_connections had no
     RES.md-cited metric or requirement (unlike phase, which model
     verification supplied A/B/C kW numbers for) -- dropped entirely
     rather than left as a documented no-op, per CLAUDE.md's own "no
     fake outputs" rule and RES.md's explicit "implement... or delete
     the placeholders" instruction.

  3. Debug prints ungated -- FIXED. HybridPlacement takes a `verbose`
     constructor flag (default False); every print (topology graph
     dump, bus loads, source/regulators, per-load branch) now gated
     behind it. placement/select_meters.py exposes --verbose on the
     CLI, off by default -- a 32-run sweep no longer prints the full
     topology graph 32 times.

  4. `from pickle import load` / duplicate `defaultdict` import / unused
     `Counter` -- FIXED by the rewrite (placement/placement_strategy.py
     imports only what it uses: ABC, abstractmethod, defaultdict, math,
     random).

  5. _compute_depths BFS/loads-annotation interleaving (O(V*L)) --
     FIXED structurally: feeder_context.compute_depths() is now a pure
     function returning {bus: depth}, touching no `loads` list at all;
     annotation happens once, separately, in FeederContext.annotate_loads().
     The bug cannot recur because the two concerns are no longer in the
     same function.

  6. _get_utility_nodes(network) called twice in select() -- FIXED:
     called once, inside FeederContext.__init__(), stored as
     self.utility_nodes.

  7. Score weights not normalised -- FIXED. backbone_bonus was 1.5 (not
     a 0/1 indicator), making its effective contribution 0.20*1.5=0.30
     -- equal to kw_score's 0.30 -- and pushing the achievable score
     total to 1.20, not 1.00, against nominal weights that themselves
     summed to 1.10. Fixed in two parts: backbone is now a genuine 0/1
     indicator (on_backbone), and the four nominal weights
     (0.30/0.20/0.40/0.20) are divided by their sum (1.10), preserving
     their original relative emphasis exactly, so kw=0.2727,
     depth=0.1818, downstream=0.3636, backbone=0.1818 (WEIGHT_KW /
     WEIGHT_DEPTH / WEIGHT_DOWNSTREAM / WEIGHT_BACKBONE class
     constants in placement_strategy.py) -- these are the numbers for
     the paper.

  Meter ceiling: HybridPlacement, RandomPlacement and DegreePlacement
  all raise ValueError at construction if target_meters > 85 (distinct
  load buses; model verification: 85 of 91 -- S49a/b/c, S65a/b/c,
  S76a/b/c share buses), rather than silently returning fewer. Verified
  by test_target_above_ceiling_raises.
