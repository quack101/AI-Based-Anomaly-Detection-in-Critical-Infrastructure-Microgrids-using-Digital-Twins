DEFECT 1 FIX -- incremental phase balancing
----------------------------------------------------------------------
  WHAT CHANGED: _balance_phases() (a post-hoc swap pass run once over
  the completed target_meters selection) is REMOVED. Phase balancing is
  now applied at every single pick during selection
  (_pick_phase_aware()): given running per-phase kW so far, if the
  currently most under-represented phase (vs. A:1400/B:952.5/C:1137.5
  kW) has a positive deficit, the highest-scoring available candidate
  touching that phase is chosen; otherwise the plain highest-scorer
  (original behaviour) is chosen. This runs inside BOTH the main
  quota/round-robin selection and the top-up pass.

  A SECOND, NECESSARY restructuring: the outer loop used to process
  each size class'S ENTIRE quota before moving to the next class. A
  prefix shorter than the first class's quota therefore reflected only
  that one class's phase mix, no matter how phase-aware the picks
  within it were -- incremental balancing alone did not fix nesting
  until classes were also interleaved GLOBALLY (one pick per class per
  round, cycling, via a rotating per-class branch queue that preserves
  branch-diversity cycling across successive turns for that class).
  This is documented in _representative_selection's docstring as the
  reason the first attempt at this fix did not close the gap.

  DIVERGENCE DID NOT FULLY CLOSE -- reported, not forced. Max remaining
  |diff| is 3.18pp (count=45); 5 of 8 counts are now under 1pp. Why it
  doesn't close to zero: a single append-ordered ranking cannot be
  simultaneously phase-optimal at every prefix length -- greedy
  incremental balancing is a genuinely different objective from "each
  length's own optimum," and quota-rounding introduces additional
  boundary effects at specific counts (round(target*n_class/total)
  crossing an integer at slightly different points for different
  targets). This is a property of the problem, not an implementation
  shortfall to keep chasing.

  THE COST, stated plainly: independent construction's OWN phase-
  balance quality got WORSE at 6 of 8 counts (e.g. count=49: 0.58pp ->
  3.16pp; count=45: 0.67pp -> 3.83pp), because the post-hoc swap pass
  it replaces was a genuinely more powerful optimizer FOR THE FINAL SET
  SPECIFICALLY -- it could see the whole selection and correct earlier
  choices; the incremental picker never revisits a choice once made.
  Nested construction improved correspondingly (e.g. count=45: 6.12pp
  -> 0.65pp). Net effect on Hybrid-vs-Random: Hybrid still beats
  Random's MEAN phase-deviation at 7 of 8 counts (all but 15), but only
  clearly beats Random's mean+1std band at 1 of 8 (count=60) -- down
  from 7 of 8 before the fix. This is a real, reportable narrowing of
  Hybrid's phase-balance advantage margin, traded for phase-balance
  actually surviving nesting. Whether that trade is worth it depends on
  which construction Phase 4/12 ends up using -- flagged, not decided
  here.

  COMMUNITY VARIANTS' divergence is UNCHANGED (their allocation logic
  was not touched -- Defect 1's scope was HybridPlacement specifically,
  per the task). Community12 and Community4's independent/nested
  divergence remains as large as before (up to 6.95pp at count=49 for
  Community12) -- this task did not fix that, and does not claim to.

DEFECT 2 FIX -- consistent tie-break on multi-load buses
----------------------------------------------------------------------
  RULE CHOSEN (now applied by ALL FOUR strategies uniformly): where a
  bus hosts more than one Load object (S49a/b/c, S65a/b/c, S76a/b/c),
  the HIGHEST-kW load is that bus's sole representative; ties (none
  occur in this feeder's data) would go to the first-encountered load
  in input order. This is _one_load_per_bus(), already used by Random/
  Degree/Community -- HybridPlacement now calls it too, as literally
  the first line of select(), before size classes or scores are even
  assigned.

  VERIFIED: at count=85 (the ceiling), all 5 strategies now select the
  IDENTICAL 85 buses with IDENTICAL phase composition (max deviation
  0.9732pp for every one of Hybrid/Degree/Community12/Community4/
  Random(seed0)) -- confirmed by direct comparison, not just equal
  metric values. Previously Hybrid alone showed 2.24pp at the same
  forced bus set, because it picked s49a/s65a/s76a via its own score-
  based tie-break while the others picked s49b/s65c/s76a via highest-
  kW. That 3-bus discrepancy is gone.

     identical-phase-composition selection across all 5 strategies at
     the ceiling. This was a clean fix with no discovered trade-off.

  2. Defect 1 (incremental phase balance) substantially narrows
     independent/nested divergence (from a 4-8pp gap to under ~3.2pp,
     mostly under 1-2pp) but does not eliminate it, and the elimination
     that DID happen came partly at the cost of independent
     construction's own absolute phase-balance quality in the low-to-
     mid count range. Both facts are reported together per the task's
     instruction not to force convergence and not to hide costs.

  3. A second restructuring (global class interleaving, not explicitly
     asked for but necessary to make Defect 1's fix actually work)
     incidentally widened the branch-diversity knee's open window
     (closes at ~85 instead of ~80) and improved several branch-
     diversity values outright. Reported as a real, unplanned benefit.

  4. Community12/Community4's independent/nested divergence is
     untouched and remains large (up to ~7pp) -- this task's Defect 1
     was scoped to HybridPlacement only, per the task description's own
     framing of the defect as specifically about Hybrid's swap pass.
