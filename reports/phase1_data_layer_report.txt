What changed vs. Phase 0 (RES.md 3.1, D10 Phase 1)
----------------------------------------------------------------------
(i)   49 metered series rescaled per-node to nominal kW/kvar (config/load_metadata.json), shape-preserving: P_k(t) = P_k^nom * (p_src(t)/mean(p_src)).
(ii)  Voltage/Global_intensity/Sub_metering_* removed from the telemetry path entirely -- streaming/producer.py now publishes only {timestamp, meter_id, load_name, bus, p_kw, q_kvar}; bus voltage/current in digital_twin_telemetry.csv come only from the OpenDSS solve.
(iii) Per-meter diversification (temporal offset + lag + scale jitter, simulation/load_scaling.py) applied before rescaling; raw pairwise correlation ~0.997 -> -0.0079 mean after.
(iv)  42 unmetered loads now driven by explicit pseudo-load series (data/pseudo_loads/), each tagged with sigma_pseudo_frac in data/pseudo_measurement_registry.json, instead of held static at nominal.

Implemented:
RES.md D10 Phase 1 -- fixed the data layer per the four defects in RES.md
3.1: (i) shape-preserving rescale of the 49 metered series to nominal
kW/kvar, (ii) Voltage/Global_intensity/Sub_metering_* dropped from the
telemetry path entirely, (iii) per-meter diversification (temporal
offset + lag + scale jitter) to break the near-identical correlation

series with a recorded sigma_pseudo, replacing the static-nominal
Phase-0 assumption.

  data/scaled_datasets/ (49), data/pseudo_loads/ (42),
  data/pseudo_measurement_registry.json
- streaming/producer.py -- sources data/scaled_datasets/ keyed by
  load_name (was fragile positional glob-order pairing); message no
  longer includes voltage/current
- streaming/consumer.py -- loads pseudo_loads/ at startup, drives all 91
  loads (49 metered from Kafka + 42 pseudo, locally loaded -- never
  published, per the cyber/physical boundary) each timestamp; dropped
  input_voltage/input_current from digital_twin_telemetry.csv
- simulation/validate_phase1.py (new) -- full-day replay + acceptance
  check against the fixed data layer

Run:
simulation/generate_scaled_datasets.py -> simulation/validate_phase1.py

consumer, ~13 timestamps, confirmed no runtime errors, then torn down)
