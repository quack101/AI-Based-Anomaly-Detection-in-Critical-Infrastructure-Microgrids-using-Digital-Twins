----------------------------------------------------------------------
2. The Jacobian -- built analytically from the compiled circuit's Y-bus
----------------------------------------------------------------------
Standard AC power-flow injection/branch-flow Jacobian (Sayghe eq. 2-3
generalised per-phase), differentiated by hand from the closed-form
algebraic P(V,delta)/Q(V,delta)/|I|(V,delta) expressions -- never by
re-solving OpenDSS at perturbed states. Two scales:
  - Bus injection rows (P_injection, Q_injection, zero-injection,
    pseudo-measurements): FULL system Y-bus row for the target phase-
    node (placement.electrical_distance.get_system_y_index()).
  - Branch/head flow rows (P_flow, Q_flow, I_magnitude_branch, P_head,
    Q_head, I_magnitude_head): that ELEMENT's own primitive Y
    (CktElement.YPrim()) -- captures genuine 3-phase mutual coupling
    within one branch, not the whole network row. The substation head's
    terminal 2 is the Vsource's fixed internal EMF (not a state) --
    treated as a "one-sided branch" against a constant, mirroring how
    the 3 source angles are handled.
  H's row order is built in the SAME single pass that would build z
  (registry.enabled_entries() order) -- asserted equal, per RES.md's
  explicit silent-wrong-answer warning about mismatched z/H ordering.

VERIFIED (tests/test_observability.py, 6 tests): every row-builder
(bus injection, branch flow, current magnitude, head P/Q) checked via
finite-differencing the module's OWN forward power-flow formula --
never OpenDSS a second time. One real bug caught and fixed this way: an
index-collision between the V-block and delta-block (delta_index was
0-based instead of offset past the V-block, so V and delta
contributions were silently overwriting each other in the same row
array) -- confirmed via the FD check landing on a completely wrong
column before the fix, and matching to 1e-6 after. Current-magnitude
rows needed a much smaller finite-difference epsilon than power rows
(|I| is near-zero at flat start, since neighbouring flat-start voltages
are nearly identical -- a large perturbation overshoots the local-
linear regime); documented in the test, not a code defect.

SCOPE NOTE -- Y-bus load contamination. OpenDSS's system Y-bus folds in
constant-impedance/current load admittances (Model != 1) at their
CURRENTLY-SET value, confirmed empirically (bus 6.3's diagonal, where
Model=2 load s6c attaches, shifts when s6c's kW is scaled). A pure
state-estimation H should be topology-only. Measured magnitude of the
contamination at a representative well-connected node: ~0.1-1% of the
nodal admittance. Disabling all loads and re-solving to obtain a load-
free Y-bus was tested and works, but introduces its own uncertainty
(regulator taps may respond to a near-zero-load operating point rather
than the nominal one). RANK is a structural, not numeric, property and
is essentially never changed by a perturbation this small -- this
module uses the standard system Y-bus (loads at as-authored nominal
values, one normal solve), not a load-disabled variant. Stated here,
not a silent shortcut.

3. Zero-injection phase-nodes
----------------------------------------------------------------------
Enumerated PER (bus, phase) from the compiled circuit -- every Load
object's actual NodeOrder/NumPhases, not a bus-level approximation.

  Zero-injection phase-nodes: 183 of 278  ->  366 exact constraint rows (P=0, Q=0)

(An earlier bus-level approximation taken during scoping this task
found 125 -- that check marked a WHOLE bus non-zero-injection if ANY
load touched it at ANY phase, incorrectly excluding that bus's OTHER,
genuinely load-free phases. The phase-resolved 183 is the correct
figure and the one used throughout this report; the 125 was a rough
estimate superseded by the actual enumeration, not a discrepancy in
the enumeration itself.)

Enforced as HARD LAGRANGIAN EQUALITY CONSTRAINTS (Sha25 Sec II eq. 1-6)
for the RANK/observability test -- i.e. stacked as additional exact
rows alongside the noisy measurement rows when testing whether the
combined linear system uniquely determines x. They are EXCLUDED from
the WEIGHTED normal-equations matrix H^T W H (see Sec 5) -- exactly the
conditioning damage Sha25 motivates the Lagrangian form to avoid.

cond(H^T W H): INFINITE at every single step listed above, in BOTH
variants. This is a real, and CORRECT, finding, not a gap in the
analysis: m(weighted) never reaches dim(x)=553 at ANY step (359/367 at
the maximum), so the noisy-measurement-only WLS normal-equations matrix
is ALWAYS singular by construction, regardless of how many sensors are
added -- the classical WLS estimator, as narrowly formulated (weighted
measurements only, no equality constraints folded in), can NEVER be
well-posed on this feeder without the zero-injection rows INSIDE it.
Sha25's own point, independently reconfirmed: a real AC-DSSE here MUST
use the Lagrangian-constrained formulation (Phase 7's job) -- trying to
report a finite cond() for the weighted-only block would have meant
either mis-scoping zero-injection as a high-weight pseudo-measurement
(exactly what Sha25 warns against) or reporting a number that doesn't
answer the question asked.

----------------------------------------------------------------------
5. FULL RANK -- achieved, and only with one specific configuration
----------------------------------------------------------------------
YES, full rank (dim(x)=553) IS achieved -- but ONLY with the MULTIPHASE
registry variant's MAXIMAL configuration (meters P,Q,V + head + branch
+ zero-injection + pseudo, 733 total rows): rank = 553/553 EXACTLY, and
n_critical = 0 (no single measurement's removal breaks observability
anywhere in that configuration).

The DEFAULT variant's identical maximal configuration (725 rows) NEVER
reaches full rank: capped at 550/553, 147 critical measurements,
REGARDLESS of what else is added. Null-space analysis of the maximal-
config default-variant H (SVD, 3 near-exactly-zero singular values,
~1.4e-6 vs the next smallest at 3.0e-3) shows the 3 unconstrained
dimensions are, with no ambiguity, EXACTLY bus 48's three phase-nodes
(48.1/48.2/48.3 -- V and delta at S48's B and C phases dominate the
first three right-singular vectors at >60% weight each; the fourth-
smallest singular value, 3e-3, jumps to a completely different part of
the network).

Bus 48 hosts S48, `New Load.S48 Bus1=48 Phases=3 Conn=Wye` -- one of
only TWO genuinely 3-phase loads on this feeder (with S47; see Sec 7).
The default registry meters S48 on its primary phase only (m=98's
scoping decision, RES.md D10 Phase 2). Phases B and C at bus 48 are
NOT zero-injection nodes (S48 draws real, nonzero power there) and are
NOT separately metered -- so no sensor in the default registry, at ANY
step of the cumulative sweep, EVER touches those two phase-nodes'
states directly. This is not a subtle numerical artifact; it is a
structural, exactly-diagnosable hole traceable to one specific modelling
shortcut.

6. Registry variant decision
----------------------------------------------------------------------
DECISION: adopt the MULTIPHASE variant (m=106).

Evidence, not assertion:
  - Full rank (553/553) is achieved ONLY with multiphase's maximal
    config; default's maximal config is permanently short by exactly
    the 3 dimensions traced to S48's unmetered phases (Sec 5).
  - n_critical drops from 147 (default, maximal config) to 0
    (multiphase, maximal config) -- not a marginal improvement.
  - The gap is not diffuse "under-coverage somewhere" -- it is provably
    caused by the single-phase-metering shortcut on the one load type
    (genuinely 3-phase Wye) that shortcut actually affects, exactly the
    failure mode this task asked to check for: "If S47/S48 appear as
    critical measurements under the base variant but not the multiphase
    one, that is an artifact of the single-phase-metering shortcut."
    Confirmed directly: neither S47 nor S48's phase-A entries appear in
    either variant's maximal-config critical set (both have enough
    surrounding redundancy once zero-injection/pseudo are present) --
    the artifact isn't "S47/S48 are critical," it's the STRUCTURAL RANK
    HOLE their B/C phases leave when unmetered, which is a stronger,
    more definitive form of the same finding than a critical-measurement
    flag would have been.

----------------------------------------------------------------------
"49x(P,Q) is far from observable; zero-injection constraints are the
decisive addition; head + branch units then supply the redundancy that
makes residuals meaningful. At the 85-bus ceiling m=170 against n=553,

HOLDS, confirmed quantitatively:

    observable, exactly as predicted.

    second, before head/branch.
  - Head: +9 rank (110->101 rows->rank in default) -- modest but real,
    exactly the "operationally free, high-value" sensor RES.md

  - Branch: the single largest jump before zero-injection (+104 rank,

  - Zero-injection: THE decisive addition, confirmed -- +303 rank in
    one step (205->508 in default), taking rank/dim from 37% to 92% in
    a single addition that costs nothing (183 nodes' worth of exact,
    free constraints).
  - Pseudo: closes most of the remainder (508->550 default, 516->553
    multiphase).
  - Tier-2 sub-study 4A (Part B) independently reconfirms the "meters
    alone" half of this from the STRATEGY-COMPARISON angle: at every
    density up to 85 (m=170) and every one of 5 placement strategies,

----------------------------------------------------------------------
3. Security index alpha_k -- method and limitation
----------------------------------------------------------------------
alpha_k = min ||Hc||_0 s.t. H(k,:)c=1 (Sayghe eq. 38), NP-hard in
general. Relaxed to an L1 linear program: min ||Hc||_1 s.t. H(k,:)c=1,
solved via scipy.optimize.linprog (HiGHS). ~5-15ms per solve; 3,850+
solves completed in under 100s total. LIMITATION, stated per RES.md's
instruction: L1 is a convex proxy for L0 and can over- or under-
estimate the true sparsest solution when H's columns are not
sufficiently incoherent -- used here because exact L0 minimisation over
a 553-dimensional c is combinatorial and RES.md explicitly authorises
the relaxation. One alpha_k per metered node (its P_injection row is
the representative k; Q_injection was not separately computed --
stated scoping choice, not an oversight).

----------------------------------------------------------------------
4. Hybrid placement score vs. alpha_k -- correlation
----------------------------------------------------------------------
Pearson r = -0.0393 (n=333 meter-count pairs, all 8 Hybrid counts
pooled).

THIS NUMBER IS NOT MEANINGFULLY INTERPRETABLE AS "WEAK CORRELATION" --
it is a near-zero coefficient computed against a variable (alpha_k)
that has ESSENTIALLY ZERO VARIANCE (1.000 +/- LP-solver tolerance
noise, per Sec 2). Pearson correlation against a near-constant is
statistically degenerate: the coefficient is dominated by numerical
noise in the fourth decimal place of alpha_k, not by any real
relationship between hybrid score and security. Reporting it as
"correlated" or "uncorrelated" would both overstate what -0.04 actually
measures.

The HONEST answer to RES.md's question ("does the alpha_k ranking
correlate with the hybrid placement score?") is: the question is MOOT
at the meters-only configuration, because alpha_k does not meaningfully
vary there AT ALL -- every meter, regardless of hybrid score, sits at
the same (minimal) security level. This is itself the N2-relevant
finding RES.md anticipates two possible outcomes for ("correlated means
the coverage heuristic is a cheap vulnerability proxy; divergent means
coverage-optimal metering is not attack-robust") -- the actual outcome
is a THIRD case neither anticipated: coverage-optimal metering is not
even DIFFERENTIATED on security, let alone correlated or divergent,
until zero-injection/other constraints are added. A meaningful
correlation test would need alpha_k computed WITH zero-injection folded
into H (so meters are no longer uniformly alpha_k=1) -- not attempted
here; Tier 2's brief was specifically the meter-placement comparison,
and this is flagged as a natural follow-up, not silently worked around.

5. Strategy fixes applied before this sweep
----------------------------------------------------------------------
CommunityDetectionPlacement degeneracy (task's own diagnosis: "kW-
proportional allocation across 12 communities leaves most with zero").
VERIFIED empirically before fixing, and the exact mechanism is more
specific than the allocation FORMULA: the existing largest-remainder
apportionment was already exact (sums to target_meters correctly at
every count) -- INDEPENDENT construction at count=9 left only 2 of 9
communities-with-candidates at zero, not "most". The real degeneracy
was in NESTED construction's SELECTION ORDER: select() built `selected`
by BLOCK-CONCATENATING each community's full allocation (all of
community 0, then all of community 1, ...) -- so a nested run's first-9
prefix (sliced from an 85-meter selection) came ENTIRELY from whichever
1-2 communities sorted first: only 2 of 9 communities represented at
count=9, unchanged through count=26.

FIX applied (placement/placement_strategy.py): (a) largest-remainder
allocation, now followed by a MINIMUM-SHARE top-up -- once every
community is floored to >=1 (feasible whenever target_meters >= number
of communities, guaranteed by conservation of the fixed total), donate
one meter to each zero-share community from the currently-largest
allocation; (b) ROUND-ROBIN selection order (one pick per community per
round, mirroring HybridPlacement's own branch-queue pattern) replacing
block concatenation. VERIFIED after the fix: nested count=9 prefix now
represents 9 of 9 communities (was 2 of 9); independent count=9
allocation represents 9 of 9 (was 7 of 9); all 8 target counts still
honoured exactly; full 94-test suite (pre-existing 88 + this session's
new 6) still passes -- no regression.

Reference configuration (config/reference_configuration.json):
target_meters=49 (57.65% of 85), status "provisional, retained for
continuity with earlier runs, carries no optimality claim". All four
placement-strategy constructors (Hybrid/Random/Degree/
CommunityDetection) now default to this value via
REFERENCE_TARGET_METERS rather than each hardcoding its own literal 49.

LIMITATIONS
======================================================================
  - Y-bus load contamination (Part A Sec 2): system Y-bus includes
    Model!=1 load admittances at nominal value; ~0.1-1% effect at a
    representative node, judged immaterial to rank conclusions, not
    eliminated.
  - cond(H^T W H) is reported as infinite everywhere in this report by
    design (Sec 4/Part A) -- this is the correct answer to "is the
    weighted-only WLS normal-equations matrix invertible," not a
    missing number. A finite conditioning number for the CONSTRAINED
    (Lagrangian) system is a Phase-7 estimator-design question, not
    attempted here.
  - alpha_k's L1 relaxation is a convex proxy for an NP-hard L0
    problem (Part B Sec 3) -- can mis-rank in either direction when H's
    columns are coherent; not validated against exact L0 on a smaller
    sub-problem in this pass.
  - The hybrid-score/alpha_k correlation (Part B Sec 4) is reported at
    the meters-only configuration, where alpha_k is nearly constant --
    a genuinely discriminating version of this test needs zero-
    injection folded into H, not attempted here.
  - Tier 2 used independent construction only, not nested -- Tier 1
    already covers that axis for placement quality; this report does
    not re-litigate it for the new observability/security metrics.
  - sigma_pseudo (10% of nominal reading, used only to weight
    H^T W H's excluded-from-rank pseudo block) is a Phase-4-scope
    placeholder, wider than Phase 2's 1% AMI figure but not the
    Phase-5 empirical estimate RES.md's own Phase-5 section requires.
